# 스토리라인 규칙 — 답 먼저, 근거는 묶어서, 제목만 읽어도 통하게

## 1. 전달 모드를 먼저 정한다 (Duarte Slidedocs / Storytelling with Data)

| 모드 | 누가 어떻게 보나 | 글자량 | 제목 | 노트 |
|---|---|---|---|---|
| `live` | 발표자가 설명, 청중은 듣는다 | 적게 (archetype `max_chars.live`) | 45자 이내 | speaker_notes 필수 |
| `pre_read` | 혼자 읽는다 (보고서형, 정부 pre-read) | 많게 (`max_chars.pre_read`) | 60자 이내 | 선택 |
| `hybrid` | 발표 후 배포 | 중간 | 52자 이내 | 권장 — 부록에 상세 |

같은 덱을 두 용도로 쓰지 않는다. 발표 덱을 배포용으로 바꿀 때는 부록과 노트를 늘리는 것이지 본문 글자를 줄이는 것이 아니다.

## 2. 피라미드 (Minto)

```
핵심 결론 (한 문장, 청중이 가져갈 답)
 ├─ 근거 1  ── 데이터·사례·분석
 ├─ 근거 2  ── …
 └─ 근거 3  ── …   (3개 권장, 3~5개 상한, MECE: 같은 종류끼리)
       ↓
 실행안 · 요청하는 결정
```

- `executive_summary`에 답과 근거를 먼저 둔다. 배경 설명으로 시작하지 않는다.
- 수직 논리: 각 슬라이드 본문이 그 슬라이드 제목을 증명한다.
- 수평 논리: 같은 층의 근거는 같은 종류(이유만, 단계만, 옵션만)다.
- 설득이 필요하면 도입부에 SCQA(상황→문제→질문→답)를 2~3문장으로 압축해 넣되, 라벨은 보이지 않게 한다.

## 3. 액션 타이틀

본문 슬라이드 제목은 **증명하거나 반박할 수 있는 주장 문장**이다.

| 약한 제목 | 액션 타이틀 |
|---|---|
| 시장 현황 | 행사형 AI 체험 시장은 단발 구축에서 반복 가능한 템플릿 플랫폼으로 이동하고 있습니다 |
| 시스템 구성도 | 공통 런타임과 플러그인 구조를 분리하면 신규 체험을 독립적으로 배포할 수 있습니다 |
| 추진 전략 | 템플릿·SDK·운영 콘솔을 3단계로 구축해 초기 매출과 확장성을 함께 확보합니다 |
| 기대 효과 | 플랫폼화하면 행사별 개발기간과 운영 오류를 동시에 줄일 수 있습니다 |

규칙
- 2줄 이내. 넘으면 글자를 줄이지 말고 문장을 줄인다 (lint `title-too-long`).
- 서술어로 끝난다 (~합니다/~입니다/~있다). 명사형 토픽 라벨은 lint `title-topic-label`로 차단.
- 마침표 없음. 숫자가 있으면 제목에 넣는다 ("6.5주에서 3주 이내로").
- 표지·섹션 구분·부록·목차만 토픽 제목 허용.

## 4. 고스트덱 검사 (ghost deck)

빌드 전에 `pptx.py lint spec.json --ghost`로 제목만 출력해 읽는다.
제목만 이어 읽었을 때 하나의 이야기가 되면 통과. 안 되면 슬라이드를 만들기 전에 순서·제목을 고친다.
이 검사는 사람이(또는 모델이) 읽고 판단한다 — 기계 검사가 아니다.

## 5. 스토리 패턴 (communication_mode)

| mode | 흐름 | 적합 |
|---|---|---|
| `pyramid` | 결론 → 근거 → 실행 → 결정 | 임원 보고, 컨설팅 |
| `briefing` | 배경 → 현황·문제 → 방향 → 세부계획 → 체계·일정·예산 → 기대효과·건의 | 정부 보고 (관행 목차; 공식 규정 아님) |
| `narrative` | 상황 → 긴장 → 해결 → 증거 → 제안 | 제안서, 영업 |
| `instructional` | 목표 → 개념 → 예시 → 연습 → 요약 | 교육 |
| `showcase` | 비전 → 제품 → 데모 → 영향 → 초대 | 키노트 |

정부 briefing 관행 목차: 추진배경 → 현황 및 문제점 → 추진방향 → 세부 추진계획 → 추진체계 → 추진일정 → 소요예산 → 기대효과 → 건의.
이 목차는 실무 관행이며 행정안전부 등의 공식 규정으로 확인되지 않았다. 기관이 양식을 주면 그 목차가 우선한다.

## 6. 마무리 슬라이드

마지막은 `conclusion` 또는 `recommendation`: 답·결정·다음 단계가 화면에 남는다. Q&A 동안 보이는 슬라이드다.
"감사합니다"만 있는 슬라이드는 lint가 차단한다 (`thank-you-ending`).

## 7. 분량

- live: 장당 1.2~2분. 20분 발표 = 본문 10~14장.
- 10장 초과면 `agenda`(목차)와 `section_divider`를 둔다. 10장 이하면 생략.
- 같은 아키타입 3장 연속이면 합치거나 형식을 바꾼다 (lint `layout-streak`).
- 본문 이해에 필요 없는 상세는 `appendix`로.
