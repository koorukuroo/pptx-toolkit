# 정부·공공기관 자료 규칙 (`government_kr`, `public_policy`)

정부형은 "파란 제목 바"가 아니라 **정보 구조·근거·절제·접근성**으로 만든다. 기관이 승인 템플릿을 주면 그것이 모든 선호보다 우선한다 (`template-workflow.md`).

## 1. 공식 아이덴티티 (정부상징 디자인 가이드, 행정안전부 2017)

| 항목 | 값 | 비고 |
|---|---|---|
| 정부청색 | RGB 0/55/100 `#003764` (PANTONE 2955C) | `government_kr` primary |
| 정부적색 | RGB 228/3/46 `#E4032E` (PANTONE 1935C) | accent — 경고·핵심 강조에만 |
| 정부회색 | RGB 87/87/87 `#575757` | 보조 |
| 보호공간 | 상징 반지름 R의 1/10 = r, 주변 **5r** 비움 | 문자·이미지 침범 금지 |
| 최소 크기 | 화면 20px (권장 24px 이상), 인쇄 8mm | |
| 유색 배경 | 테두리형 사용, 명도 대비 40% 이상이면 기관명 백색 | |
| 금지 | 회전, 변형, 색 변경, 그라데이션, 그림자, 태극 형태 테두리, 엠블럼과 기관명 조합 | |

- 로고·상징은 **기관이 제공한 승인 자산 파일**만 `assets.logo`로 넣는다. 다시 그리거나 비슷하게 만들지 않는다.
- `brand_mode: neutral`인 "정부형 스타일" 자료는 공식 승인을 암시하지 않는다 (상징 미사용).
- **대한민국정부상징체**는 기관명 표기 전용 서체다. 가이드가 "서식류·홍보물의 제목·본문으로 쓰지 않는다"고 명시하므로 슬라이드 제목·본문 폰트로 지정하지 않는다. 영리 목적 사용은 문체부 협의 대상.
- HY헤드라인M·HY견고딕 등 한컴 번들 폰트는 라이선스 분쟁 사례가 있어 기본 폰트로 지정하지 않는다.
- 안전한 한글 폰트: Paperlogy(OFL), Pretendard / Pretendard GOV(OFL), Noto Sans KR(OFL), 나눔스퀘어(OFL). 폰트 파일은 스킬에 동봉하지 않는다.

## 2. KRDS(범정부 디자인 시스템) 토큰을 빌린다

- 3계층 토큰(primitive → semantic → component). 프로파일 토큰이 primitive, 아키타입이 component에 해당.
- **60-30-10**: 배경·중립 60%, 보조 30%, 주조 10%. **강조(point)는 5% 이하.** (`ratios` 토큰)
- 대비: 본문 4.5:1 이상, 큰 글자(18pt 이상 bold / 24px) 3:1 이상. lint `contrast-low`가 토큰을 검사한다.
- 색만으로 상태를 구분하지 않는다 — 라벨·패턴·텍스트를 함께 둔다 (흑백 인쇄 대비).
- 참고 primitive (KRDS tokens): primary-50 `#256EF4`, secondary-50 `#346FB2`, gray-90 `#1E2124`, gray-5 `#F4F5F6`, danger-50 `#DE3412`, success-50 `#228738`, warning-50 `#9E6A00`, info-50 `#0B78CB`. 웹 색이므로 인쇄·투사 자료에는 정부청색 계열을 주조로 두고 KRDS는 상태색·회색 계열에 쓴다.
- 글자 굵기는 400/700 중심, 최대 4종. 행간 150% 내외.

## 3. 항목 기호·표기 (행정업무운영 편람)

- 번호 체계 8단계: `1. → 가. → 1) → 가) → (1) → (가) → ① → ㉮`. 하위 항목은 한 글자(2타)씩 들여쓴다. 항목이 하나면 기호 생략.
- 실무 기호 위계(관행): `□ → ○ → - → ※(또는 ·)`. `government_kr` 프로파일의 `list.markers`가 이 순서로 들어간다.
- 날짜 `2026. 10. 17.`(온점·띄어쓰기), 시간 `15:20`, 금액은 아라비아 숫자 + 단위, 큰 금액은 `억원`으로 통일하고 표마다 `단위:` 명시.
- 개조식(명사형 종결)은 관행이다. 다만 제목은 액션 타이틀(서술형)로 두는 편이 결론 전달에 낫다 — 기관 양식이 개조식 제목을 요구하면 양식을 따른다 (`lint`의 title 규칙은 참고로만).
- 2026년 행정안전부 「AI시대 행정문서 작성 가이드라인」 방향(보도자료 기준): 주어·서술어 명확히, 복잡한 셀 병합 금지, 표준 번호 체계. 표는 병합 없이 단순 격자로.

## 4. 정보 구조 (관행 목차)

추진 배경 → 현황 및 문제점 → 추진 방향(목표·원칙) → 세부 추진계획(과제) → 추진체계(TF·역할) → 추진 일정 → 소요 예산 → 기대효과 → 건의(결정 요청)

- 통계 슬라이드마다 **출처·기간·정의**(n, 집계 기준)를 `source_note`에 쓴다.
- 확정 / 추정 / 목표 / 계획을 구분해 표기한다. 미래 연도 수치에는 "(추정)", "(목표)", "(안)". `audit`의 `estimate-unmarked`가 잡는다.
- 예산: 단위(억원/백만원) 통일, 부가세 포함 여부, 국비·지방비 매칭 전제, 포함·제외 범위.
- 일정: 연도·분기 단위 로드맵 + 마일스톤(개통·심사·보고).
- 사진은 현장·지도·절차도·데이터 우선. 홍보성 스톡·악수 사진·장식 아이콘 지양.

## 5. 정부형 시각 언어 (프로파일 토큰이 구현)

- 흰 배경, 넓은 여백, 정부청색 주조, 빨강은 경고·핵심 하나에만.
- 제목 앞 로마 숫자 칩(Ⅰ·Ⅱ·Ⅲ)으로 장(章)을 표시 — hwpx-toolkit `report` 테마와 같은 체계.
- 얇은 구분선과 연한 회색 면. 그림자·그라데이션·둥근 카드 없음.
- 표: 머리글 아래 굵은 선, 행 사이 가는 선, 세로선 없음, 합계 행 강조.
- 발표용(live)이면 글자 18pt 이상, 읽기용(pre_read)이면 14~15pt에 밀도 허용. "항상 여백 크게·글자 적게"를 정부 읽기 자료에 일률 적용하지 않는다.

## 6. 제출·배포 전 확인

- `pptx.py qa deck.pptx --spec spec.json --bleed` 통과.
- 상징·로고는 승인 파일 그대로, 보호공간 확인(렌더 PNG에서).
- PDF 변환 후에도 표·각주가 읽히는지 (`render`의 PDF).
- 글자 포함 이미지(차트 캡처)를 넣지 않았는지 — 차트는 네이티브.
