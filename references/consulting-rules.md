# 컨설팅 그레이드 규칙 (`consulting_grade`)

특정 펌의 로고·색·템플릿을 흉내 내지 않는다. 가져오는 것은 **문법**이다.

## 1. 슬라이드 문법

```
[킥커: 섹션 · Exhibit N]                       [트래커 ▮▯▯▯]  [DRAFT]
액션 타이틀 — 결론 문장, 2줄 이내, 모든 장에서 같은 위치·크기
┌───────────────────────────── 본문 ─────────────────────────────┐
│  전시물 하나 (차트·표·도식)        │  해석(callout) 1개          │
│  직접 라벨 · 강조색 1개            │  보조 포인트 ≤ 3            │
└────────────────────────────────────────────────────────────────┘
출처: …(기간·단위·가정)                                            n
문서명 · 대외비                                                    
```

- **한 장 = 결론 하나 + 그것을 증명하는 전시물 하나.** 두 번째 전시물은 부록으로.
- 제목은 모든 본문 슬라이드에서 같은 좌표·같은 크기 (프레임이 보장). 가장 큰 글자.
- 제목 ≤ 2줄, 능동태, 숫자 포함. "현황/전략/기대효과" 같은 라벨 금지.
- `exhibit` 번호는 차트·표가 있는 슬라이드에만, 덱 전체에서 순차.
- `sticker`: `DRAFT` / `PRELIMINARY` / `ILLUSTRATIVE` — 수치가 가설·예시임을 알린다. 확정 자료에서는 뺀다.
- 푸터: 문서명(좌) · 대외비(중) · 쪽번호(우). 날짜·태그라인·로고를 푸터에 다 넣지 않는다.
- 출처 줄: `출처: 자료명 (기간), 분석 주체. 가정·주석`. 모든 데이터 슬라이드에. 각주 번호가 필요하면 `주 1)`.

## 2. 밀도

| 모드 | 본문 글자 | 전시물 | 글자 크기 |
|---|---|---|---|
| live | 60~90단어 | 1개 | 본문 17pt, 최소 14 |
| pre_read | 120~180단어 | 1~2개(조정된) | 본문 14pt, 최소 11, 출처 8~9 |

읽기용 컨설팅 덱은 12~14pt 본문이 표준이다. 발표용에 그 밀도를 쓰지 않는다.

## 3. 스토리 패턴

| 유형 | 흐름 |
|---|---|
| 진단 | 맥락 → 성과 격차 → 근본 원인 → 우선 이슈 → 권고 |
| 전략 | 지향점 → 어디서 싸울지 → 어떻게 이길지 → 역량 → 로드맵 → 효과 |
| 비즈니스 케이스 | 문제 → 목표 성과 → 해법 → 가치 동인 → 경제성 → 리스크 → 결정 |
| 전환 | 변화의 이유 → 목표 운영모델 → 과제 → 거버넌스 → 로드맵 → KPI |

체인: 문제 → 인사이트 → 권고 → 실행 → 기대효과 가 끊기지 않게.

## 4. 전시물 규칙

- 막대는 의미 있는 순서로 정렬(크기순/시간순). 강조 1색 + 나머지 회색(`chart.highlight`).
- 직접 라벨 > 범례. 단위·기간은 제목이나 출처·`(단위: )` 라벨에. 축 제목 세로 회전은 피한다.
- 추세는 선, 비교는 막대, 구성은 누적/도넛(조각 ≤ 6), 흐름은 워터폴, 우선순위는 2×2.
- 반올림: 의사결정에 필요한 자릿수만 (소수 2자리 이상은 lint `fake-precision`).
- 색 의미 고정: 긍정 `positive`, 부정 `negative`, 합계 회색. 무지개·그라데이션·3D 금지.
- 지수화하면 "2020=100" 명기. 동일 지표는 덱 전체에서 같은 스케일.

## 5. 아키타입 매핑

| 말하려는 것 | 아키타입 |
|---|---|
| 답 + 근거 3개 + 결정 | `executive_summary` |
| 숫자 하나가 핵심 | `hero_metric` |
| 데이터가 결론을 증명 | `evidence_chart` (highlight 지정) |
| 대안·현행 vs 개선 | `comparison` (winner) |
| 단계·운영모델 | `process` (numbered/chevron/timeline) |
| 시간 축 실행 | `roadmap` |
| 시스템 구조 | `architecture` |
| 우선순위 | `matrix` |
| 비용·옵션 | `pricing_or_budget` |
| 권고 + 이유 + 다음 단계 | `recommendation` |
| 마무리 | `conclusion` |

## 6. 금지

- 사이드바·헤더 바·제목 밑줄 같은 장식 스트라이프 (칩·트래커·콜아웃 선은 의미가 있는 요소만).
- 문장마다 아이콘, 동일 크기 카드 3개 벽지, 미니 대시보드.
- 본문 페이지의 사진. 사진은 표지·섹션·사례에만.
- 결론 없는 "분석" 페이지, 출처 없는 숫자, 지어낸 벤치마크.
