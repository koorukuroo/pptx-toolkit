# 페이퍼로지식 실무 제작 규칙 (`paperlogy_business`)

페이퍼로지 강의·도서의 **공개된 원칙 제목**만 재해석했다. 유료 템플릿·예제는 복제하지 않는다. `paperlogy_business`는 코어닷투데이 내부 프로파일 이름이지 페이퍼로지 공식 스킬이 아니다.

## 1. Paperlogy 폰트

- SIL OFL v1.1, 9굵기(Thin~Black), 제작 이주임·김도균(저작권 피티앤, 2024). 상업·임베딩·수정·재배포 가능, 단독 판매 금지.
- 설치: `brew install --cask font-paperlogy` 또는 https://freesentation.blog/paperlogyfont
- 프로파일은 제목·숫자에 Paperlogy, 본문에 Paperlogy 또는 Pretendard. 폰트 미설치 환경에서는 Pretendard → Noto Sans KR → Apple SD Gothic Neo → Malgun Gothic 순으로 대체(`fonts` 커맨드로 확인).

## 2. 원칙 → 토큰·아키타입

| 공개 원칙 (제목) | 스킬에서의 구현 |
|---|---|
| 기획서의 언어는 '숫자' | `hero_metric`, `points.metric`, 큰 숫자 타이포(`bigNumber`, Paperlogy ExtraBold) |
| 보고서를 지배하는 숫자 '3' | 근거·단계·선택지는 3개 우선 (강제 아님, lint `items-too-many`는 4~6에서 경고) |
| 서술형보다 항목을 쪼개자 | `points` rows/columns, 헤딩+설명 두 층 |
| 주어와 목적어를 생략하지 마라 | 액션 타이틀은 완결 문장 |
| 기준표 작성으로 시간을 반으로 | 프로파일 토큰(여백·그리드·글자·색)을 먼저 확정 → `style-profiles.json` |
| 사방에 못을 박아 안정감 / 기준선 | 모든 아키타입이 같은 제목 위치·본문 영역·푸터 기준선 사용 (프레임) |
| '덩어리'가 핵심 / 최대한 쪼개야 아름답다 | 열 분할(`columns`)과 하airline 구분, 한 덩어리에 메시지 하나 |
| 시메트리 | 정부·공공형은 대칭(안정·공공성), 제안·키노트는 의도된 비대칭(표지 좌측 정렬 + 우측 색면) |
| 트리밍 | 이미지 1장을 `cover` 크롭(`image_focus`, 표지), 썸네일 나열 금지 |
| 여백은 둘수록 아름답다 | 본문 영역 밖 요소 금지(inspect `margin-violation`), 살짝 비는 것을 두려워하지 않는다 |
| 그레이를 잘 쓰는 자 | `ink_muted`/`ink_faint`/`line_faint` 3단 회색으로 위계, 강조색은 5% 이하 |
| 선만 잘 써도 | 굵은 선(머리글 아래 1.25pt)·가는 선(0.5pt) 두 종류만 |
| 강조의 모든 것 | 강조 순서: 문장 → 위치 → 크기 → 굵기 → 색 → 도형 → 애니메이션. 도형(박스)은 마지막 수단 |
| 세상이 바뀌었는데 아직도 아이콘? | 아이콘 대신 숫자·단어·선. 아이콘은 의미가 고정된 경우에만 |
| A vs B 비교 장표 | `comparison` (winner 열 강조) |
| 시간의 흐름 차별화 | `process timeline`, `roadmap` 마일스톤 |
| 애니메이션은 딱 하나만 | 생성기는 애니메이션을 넣지 않는다 (필요 시 PowerPoint에서 1개만) |
| 블라인드 텍스트 / 끝이 언제인지 알려주는 기술 | 트래커(섹션 진행 표시), `agenda` |

## 3. 표지

- 목차가 아니라 **약속**: 제목은 자료가 주는 결과, 부제는 범위·방법. 킥커(tagline)로 문서 성격(제안서·보고·검토).
- 키비주얼은 한 장을 과감히 크롭해 색면처럼 쓰거나(`image-or-dark`), 없으면 단색 면.
- 로고는 승인 자산만, 하나만.

## 4. 제작 속도 규칙 (스킬 운용)

- 새 덱은 `new-spec`으로 시작해 메타·루트·고스트덱(제목 목록)부터 쓴다. 디자인은 토큰이 처리한다.
- 첫 3장만 `--only 1-3`으로 빌드·렌더해 방향을 확인한 뒤 전체 생성 (샘플 게이트).
- 수정은 spec을 고쳐 다시 빌드한다. 생성된 pptx를 손으로 고치지 않는다 (고객 전달 직전의 미세 조정만 PowerPoint에서).
